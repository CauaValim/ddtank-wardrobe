# Project Architecture Rules

- Mount descriptions and attributes, clothing-set membership, and set bonuses must come from official game data; do not restore spreadsheet-based values, because the official source stays synchronized with the game.
- Event documents are stored as one row per document in `event_documents` with sections in a JSONB column, because each section type has a different shape and documents are always edited as a whole.
- Event XLSX exports patch the versioned official workbook template at the OOXML cell/media level, because rebuilding worksheets would lose the approved formatting and embedded artwork.
- Every tab of the template is described in `src/lib/eventTemplate/manifest.json` (generated by `scripts/event-template/build_manifest.py`): fields, item slots (name cell, image region, ID cell) and rows to hide. The exporter only touches mapped cells, so never hard-code cell positions elsewhere; change the generator and regenerate.
- The template lives in the private Storage bucket `event-templates` at `<version>/<fileName>` and is only accepted when its SHA-256 matches the manifest. A new template version needs a new manifest version, a regenerated manifest and a green round-trip test (`EVENT_TEMPLATE_PATH=... npm test`).
- Event sections are stored as `{ layoutId, servers, fields, sets }`; sections from the first editor (`{ type, groups }`) are converted on open by `normalizeSections`.
- Business rules that are not cell positions live in `src/lib/eventTemplate/rules.ts` (missions without limit, Daily Entry queues, recharge/consume floor ladders, exchange limit text, renewable fill), because the manifest only describes the template. Missions beyond one tab are exported as continuation tabs (`paginateSection`) and joined back on import, instead of inserting rows into the template.
- Past spreadsheets name their tabs in many ways and some layouts share the same structure (Recharge × Consume, the two Rankings), so the importer takes the layout type from the tab name and picks the layout inside that type by the merged cells in each layout's `signature` plus the fixed texts found in place; tabs below the threshold, or read with headers/ID lines as item names, are skipped instead of imported with shifted cells.
- Old servers (s1-s401, `server_group = 'old'`) and new servers (s402, `'new'`) are separate bases: documents, imported past events (`source = 'import'`, names/IDs/quantities only, no images), presets and item-usage notices are always filtered by `server_group` and never mixed.
